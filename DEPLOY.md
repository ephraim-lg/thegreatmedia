# The Great Media v2 — thegreatmediazm.com

Rebuilt 2026-09-18/19 as a single-funnel "customer acquisition system" site from the
Telegram blueprint PDF. Live on Cloudflare Worker `morning-shape-c2bc` (static assets).

## Layout
- `src/pages/*.html` — page bodies with a `<!--meta {...} -->` JSON header (title, desc, sticky, scripts, jsonld)
- `tools/build.js` — wraps every page in the shared nav/footer/pixel layout → `public/*.html`
- `public/` — the deployable site (css/site.css, js/site.js, js/apply.js, img/, _headers, _redirects, sitemap, robots, leads.html)
- `workers/tgm-leads-api.js` — the leads API worker (`tgm-leads-api`), deployed separately
- `tools/originals/*.png` — full-res Higgsfield renders (hero pipeline, leak bucket, 6 stage icons, founder portrait, CTA ripple)

## Build + preview
    node tools/build.js
    node tools/serve.js            # http://localhost:8788 — mimics extensionless HTML
    node tools/shot.js results r   # full-page screenshot to tools/shots/, reports overflow + JS errors
    node tools/e2e-apply.js        # walks the qualifier on a 390px phone, both outcomes, API stubbed
    node tools/e2e-live.js         # same against the LIVE site — creates real rows, delete them afterwards

## Deploy the site (no wrangler login needed)
1. `node tools/manifest.js` → tools/manifest.json + hash-to-file.json
2. cloudflare-api MCP: `POST /accounts/<id>/workers/scripts/morning-shape-c2bc/assets-upload-session {manifest}` → session jwt + buckets
3. `node tools/upload.js <session-jwt> '<buckets json>'` → tools/completion.jwt
4. cloudflare-api MCP: `PUT /accounts/<id>/workers/scripts/morning-shape-c2bc` multipart with ONLY a `metadata` part:
   `{compatibility_date, assets:{jwt:<completion>, config:{html_handling:"auto-trailing-slash", not_found_handling:"404-page", _headers, _redirects}}}`
   (the snippet is regenerated by the one-liner in the session; `_headers`/`_redirects` are passed as file contents, not uploaded)
- The asset manifest is replaced wholesale — always deploy the whole `public/` folder.
- `/css/*` and `/js/*` are cached immutable; the build stamps `?v=` on every script/style link, so never edit `public/*.html` by hand — edit `src/` and rebuild.

## Deploy the leads worker
Multipart `PUT /accounts/<id>/workers/scripts/tgm-leads-api` with `metadata` `{main_module:"index.js", compatibility_date:"2026-06-01", keep_bindings:["secret_text"]}` + `index.js` part (`application/javascript+module`).
`keep_bindings` is what preserves the six secrets (SUPABASE_URL, SUPABASE_SERVICE_KEY, ADMIN_KEY, RESEND_API_KEY, ALERT_EMAIL, LEGACY_WEBHOOK). Observability logs are ON (head_sampling_rate 1) — query them via `/workers/observability/telemetry/query`.

## Qualifier → data
The 7-step form posts to `POST /lead`. Known columns are used where they fit
(business_type←industry, goal←90-day goal, pages←website, audience←location, source←lead sources,
budget/timeline keys unchanged) and everything else (customer value, revenue, enquiries, ad spend,
reply time, follow-up owner, bottleneck, role, plan, fit + reason) goes into `notes` as a readable
block — there is no SQL access from this machine to add columns. The dashboard (`/leads`) shows it by
clicking a name. Not-a-fit applications are capped at score 25 and the alert subject is prefixed
`[Not a fit]`. Budget keys: low <K10k · starter K10–20k · growth K20–50k · premium K50k+.

## Gotchas learned
- `label` `change` events fire on blur = on mousedown of the Continue button. Collapsing the error
  box then moves the button before the click lands → "dead button". Errors clear only on Continue.
- Count-up numbers must never be zeroed before they're on screen (the old site showed "0K+").
- Renders are black-background PNGs: `mix-blend-mode: screen` + shadows crushed with sharp `.linear(1.1,-14)` makes them float on the page.
- `.page-hero` needs `overflow:hidden` or the glow blob adds 144px of horizontal scroll.

## 2026-09-19 additions

Update it at the start of every month (or set `left: 0` for "full — apply for next slot"). It fills every `[data-slots-line]` / `[data-slots-pill]` on home, pricing, apply and the final CTA.
- **Grand-slam offer** section on home (`#offer`) — value stack K63,000+ vs from K10,000/mo, "Live in 21 working days or first month's fee is on us", bonuses. The K-values are price anchors for scope items bought separately; edit in `src/pages/index.html`.
- **Apply flows:** `need` step → `system` (8 steps) or `website` (7 steps, skips acquisition/bottleneck, asks site job/pages/content, one-off budget bands from K7,500). `?plan=website|growth|scale|custom` pre-selects. Budget bands now five: low/starter/growth/premium/elite (system: <10k/10–20k/20–50k/50–100k/100k+; website: <7.5k/7.5–15k/15–35k/35–75k/75k+). Timeline has `now` ("this week"). Readiness question (yes/partner/notyet).
- **Gate:** not a fit if budget=low OR timeline=exploring OR readiness=notyet OR (system, customer <K1,000, starter). A 3-second "Reviewing your application" screen runs before the verdict. Not-a-fit is capped at score 25 server-side and the alert subject is prefixed `[Not a fit]`.
- No cookie bar on /apply (`.page-apply .cookie{display:none}`).
- `tools/e2e-apply.js [baseUrl]` covers system-fit, website-fit, low-budget, researching, not-ready.
